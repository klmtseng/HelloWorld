# Content Plan（每週更新規劃）

## 目標
- 讓個人網站持續有新內容，展示長期學習與輸出能力。
- 平衡「作品更新」與「技術深度」兩種內容型態。

## 更新節奏（每週）
- **週一：規劃與素材整理**
  - 確定本週主題（作品改版 / 技術文章 / 學習紀錄）。
  - 彙整截圖、程式片段、關鍵指標。
- **週三：內容產出**
  - 完成草稿（至少 1 篇短文或 1 個作品更新項目）。
  - 更新網站對應區塊與圖片素材。
- **週五：發布與回顧**
  - 上線內容、分享至社群平台。
  - 記錄讀者回饋、安排下週優化方向。

## 每週內容配比
- **新作品 / 作品進度**（40%）
  - 新增 1 個作品卡片，或更新既有作品成效。
  - 補充 before/after 截圖與技術挑戰。
- **技術文章**（30%）
  - 聚焦 1 個技術主題（如效能優化、CSS 架構、可及性）。
  - 文章結尾附上可重用範例或清單。
- **學習紀錄**（30%）
  - 每週整理 3 個學到的重點。
  - 紀錄踩坑與修正方式，形成可回顧知識庫。

## 8 週範例主題
1. 作品集首頁 v1 上線與資訊架構設計。
2. CSS 元件化策略與命名規範。
3. JavaScript 模組拆分與維護方式。
4. 響應式設計優化（手機/平板斷點調整）。
5. 作品頁加入 Lighthouse 效能優化紀錄。
6. 撰寫「從需求到介面」實作案例。
7. 分享 GitHub Pages 自動部署流程。
8. 季度回顧：最佳實踐與下一步技術學習地圖。

## 成效追蹤指標
- 每月新增內容數（目標：4 篇以上）。
- 作品頁停留時間與點擊率。
- 技術文章被收藏/分享次數。
- 每月回顧是否達成既定更新節奏。
